# Phase B: i18n and RTL (B1)

**Goal:** every user-visible string comes from a locale catalog, English and Arabic are first-class, and switching to Arabic mirrors the whole layout (`dir="rtl"`) without horizontal scrolling or accessibility regressions.

**Approach:** no new dependency. The app already renders from one store and one component tree; a flat catalog module plus a typed key space is enough for the current copy, and it keeps the CSP and bundle budgets untouched (CLAUDE.md §9: ask before adding dependencies). ICU pluralization is deliberately deferred until a screen needs it; the current keys use only `{name}` interpolation.

## Files

| File | Responsibility |
|---|---|
| `src/i18n/locales/en.ts` | Source catalog (English). `as const`, so `keyof typeof en` is the key type. |
| `src/i18n/locales/ar.ts` | Arabic catalog, typed `Record<MessageKey, string>`: a missing or extra key fails `tsc`. |
| `src/i18n/index.ts` | `Locale`, `LOCALES` (native name + direction), `translate()` with interpolation and English fallback, `isLocale()`, `otherLocale()`, `messageKeys()`. |
| `src/i18n/locales/catalog.en.ts` | Tool and category display copy (English source), keyed by `ToolId` / `ToolCategoryId`. |
| `src/i18n/locales/catalog.ar.ts` | Arabic tool and category copy; the `Record<ToolId, ToolCopy>` and `Record<ToolCategoryId, string>` types make a missing or extra entry a `tsc` error. |
| `src/i18n/catalog.ts` | Locale-bound catalog copy: `toolCopy()`, `toolName()`, `toolDescription()`, `categoryName()`, with an English fallback on a gap. |
| `src/constants/tools.ts` | Catalog identity and presentation only (id, icon, color, category, MVP flag); no user-visible strings. |
| `src/i18n/useI18n.ts` | Hook returning `{ locale, dir, setLocale, t, tool, toolName, toolDescription, categoryName }`; reads the locale from the persisted UI store. |
| `src/store/toolsStore.ts` | `locale` is stored beside `darkMode` and `skin` in the existing `ui-preferences` IndexedDB record, so a language choice survives a reload with no second storage layer. |
| `src/App.tsx` | `DocumentLanguage` writes `lang` and `dir` onto `<html>` whenever the locale changes. |

## How to add a string

1. Add `'namespace.key': 'English text'` to `en.ts`.
2. Add the same key to `ar.ts` (the compiler enforces it).
3. Read it with `const { t } = useI18n()` and `t('namespace.key', { name })`.
4. Placeholders are `{name}`; a missing value stays visible (it is never rendered as `undefined`).

Tool pages use two namespaces: `tool.common.*` for copy shared by every tool page (upload zone, step words, "Back", "Remove file") and `tool.<tool-id>.*` for copy that belongs to one page. A tool page's title and description are not keys at all — read them with `toolName()`/`toolDescription()` from the catalog, so the same words appear on the card, the route and the page header.

## How to add or change a tool's copy

1. Add the name and description to `src/i18n/locales/catalog.en.ts` (keyed by `ToolId`).
2. Add the same key to `catalog.ar.ts` (the record type enforces it).
3. Read it in a component with `const { toolName, toolDescription, categoryName } = useI18n()`.
4. `src/constants/tools.ts` takes no strings: a new tool is one catalog entry plus one registry entry plus one page.

The category headings are locale data too (`categoryCopyEn`/`categoryCopyAr`), keyed by `ToolCategoryId`, so a new category needs no component change.

Release wording follows the registry, not a second list: `src/i18n/releaseState.ts` maps a registry `releaseState` to the badge keys (`home.status.*`, none for `stable`) and to the summary keys (`home.release.*`). A new state is one switch case plus one catalog key pair, not an edit per surface.

## Verification

- `npm run typecheck` proves the Arabic catalog is complete (it is a `Record<MessageKey, string>`).
- `src/i18n/i18n.test.tsx` checks the locale table, direction mapping, interpolation, placeholder safety, catalog parity and that every message is actually translated.
- `src/i18n/catalog.test.ts` checks that every catalog tool and category has copy in every locale, that the English wording is unchanged, that every Arabic name and description is actually Arabic, and that the release-facing limits survive translation (unavailable tools, PDF/A not validated, Blackout not a confidentiality boundary).
- `src/config/releaseClaims.test.ts` now reads the English catalog copy for the disabled-tool and Blackout assertions, so the claim guards follow the copy instead of the catalog. Its containment and data-counter scans read the home components together with `en.ts`, so a sentence moved into the catalog is still checked.
- `src/pages/Home.test.tsx` and `HomeBento.test.tsx` assert the Arabic hero, status badges, search placeholder and privacy block, so the chrome cannot silently stay English.
- The tool-page tests assert the Arabic upload flow (Merge PDF), the Arabic split options (Split PDF), the Arabic compress presets, the Arabic repair success screen and the Arabic OCR summary, so interpolated copy is exercised too.
- `src/i18n/i18n.test.tsx` keeps a `SAME_IN_BOTH` list for values that are deliberately identical across languages (pure interpolation templates, brand marks); add a key there only when it has no translatable words.
- Component tests assert the English defaults still read the same and that the header switches to Arabic and back.
- `e2e/i18n.spec.ts` switches the production build to Arabic, asserts `lang`/`dir` on `<html>`, checks the mirrored layout does not scroll horizontally, runs axe on the Arabic shell, and reloads to prove persistence.
- The usual gate: lint, full vitest with coverage, build, `check:bundle`, the existing e2e and Lighthouse specs.

## Known limitations in B1.1–B1.4c

- Every tool page, the AI consent dialog, the app chrome and the editor workspace are translated (B1.3a–B1.4b).
- Catalog descriptions of the migrated tools keep the fuller sentence their pages already showed (Organize PDF, Compress PDF, Repair PDF, OCR PDF), so the card and the page header stay in sync.
- Library errors stay English: `src/lib/ocr.ts` (missing language data, limits), `src/lib/pdf.ts` (invalid page ranges) and the office and image converters (`src/lib/office-*.ts`, `src/lib/image.ts`) still produce technical messages that the pages render as-is. They are diagnostic detail, not page copy; a later slice can map them to codes like Repair PDF does.
- `registry.ar.ts` has no link to the English sentence beyond the same-figures test, so a reworded English limitation can leave the Arabic behind. Change both in one commit.
- Arabic copy in B1.1 is a first draft by the agent; the owner (a native speaker) reviews it in B1.5 before release.
- No plural/ICU rules yet; if a screen needs counts, add a small plural helper and Arabic plural categories with tests.
- RTL is checked for overflow and axe on the home shell in both languages; a per-screen visual pass belongs to B1.3–B1.4.
- The language switcher lives in the header; the bento skin keeps the sidebar equivalent in B1.2 when the sidebar copy lands there.
